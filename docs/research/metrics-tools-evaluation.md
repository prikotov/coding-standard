# Сравнение анализаторов метрик для `PHP`-проекта

## Контекст

Для инициативы по метрикам поддерживаемости требовался анализатор, из машинного отчёта которого можно построить единую модель уровня класса:

- `LOC` и `LLOC`;
- `LCOM`;
- афферентная и эфферентная связанность (`Ca`/`Ce`);
- цикломатическая сложность (`CC`);
- количество методов и свойств.

Оценивались `PhpMetrics`, `PDepend` и `PhpCodeArcheology`. Цель исследования — проверить инструменты на реальном коде пакета и выбрать основу для последующего агрегатора, а не сравнить возможности только по документации.

Первичное исследование выполнено 6 августа 2026 года в рамках `TASK-metrics-tools-evaluation`. Поиск альтернатив и проверка `scc` выполнены 7 августа 2026 года после обсуждения отчёта.

## Методика

### Среда

- `PHP` 8.4.23;
- 32 `PHP`-файла в `src/`;
- `PhpMetrics` 2.10.0;
- `PDepend` 2.16.2;
- `PhpCodeArcheology` 2.11.3.

### Проверки

1. Каждый анализатор запущен на полном каталоге `src/`.
2. Проверено количество успешно обработанных файлов.
3. На пяти знакомых классах сопоставлены `LOC`/`LLOC`, `LCOM`, `Ca`/`Ce`, `CC`, методы и свойства:
   - `DtoStructureSniff`;
   - `ServiceStructureSniff`;
   - `EnumStructureSniff`;
   - `CrossModuleDomainRule`;
   - `ServiceContractDependencyRule`.
4. Отдельный минимальный пример проверял разбор атрибута `#[Attribute]`, конструкции `final readonly class` и продвигаемых свойств конструктора.
5. Для каждого кандидата оценены машинный формат, полнота полей уровня класса, лицензия и актуальность разработки.

Это проверка пригодности для данного пакета, а не доказательство корректности всех формул анализаторов.

## Общее сравнение

Все кандидаты обработали 32 из 32 файлов `src/` без ошибок. Минимальный пример `PHP` 8.4 также разобран полностью: два из двух классов попали в каждый отчёт.

|---|---|---|---|
| `PhpMetrics` 2.10.0 | `JSON`; `LOC`/`LLOC`, `LCOM`, `Ca`/`Ce`, `CC`, методы; нет количества свойств | `src/`: 32/32; пример: 2/2 | `MIT`; релиз 2026-07-21, изменения в репозитории 2026-08-02 |
| `PDepend` 2.16.2 | `XML`; `LOC`/`LLOC`, `Ca`/`Ce`, `WMC`, методы/свойства; нет `LCOM` и `JSON` | `src/`: 32/32; пример: 2/2 | `BSD-3-Clause`; релиз 2023-12-17, изменения в репозитории 2026-08-02 |
| `PhpCodeArcheology` 2.11.3 | `JSON`; `LOC`/`LLOC`, `LCOM`, `usedByCount`/`usesCount`, `CC`, методы и свойства | `src/`: 32/32; пример: 2/2 | `MIT`; релиз 2026-07-28, изменения в репозитории 2026-08-01 |

Формат ячейки: `LOC/LLOC/LCOM/Ca/Ce/CC/методы/свойства`. Знак `—` означает отсутствие поля. Для `PDepend` вместо отсутствующего единого показателя `CC` уровня класса приведён `WMC`.

### Интерпретация расхождений

- Одинаковые названия метрик не гарантируют одинаковую формулу или единицу подсчёта.
- `PhpMetrics` считает `loc` не как физический диапазон строк класса. `PDepend` и `PhpCodeArcheology` показали физический диапазон от объявления до конца класса.
- Определение `LLOC` у `PDepend` заметно отличается от двух других инструментов.
- `CC` и `WMC` не взаимозаменяемы, поэтому их значения нельзя сравнивать как одну метрику без нормализации определений.
- `LCOM` `PhpMetrics` и `PhpCodeArcheology` совпал на всех пяти проверенных классах.
- Для `CrossModuleDomainRule` `PhpCodeArcheology` показал четыре исходящие зависимости — по числу четырёх используемых внешних типов. `PhpMetrics` и `PDepend` показали три. Это частная ручная проверка, а не гарантия общей точности расчёта связанности.
- Во всех пяти классах `Ca` равен нулю: другие классы из анализируемого `src/` на них не ссылаются. Этот набор не проверяет поведение инструментов на ненулевом `Ca`.

## Оценка кандидатов

### `PhpMetrics`

Плюсы:

- зрелый инструмент;
- компактный `JSON`;
- присутствуют `LCOM`, `Ca`/`Ce`, `CC` и количество методов;
- успешно разобрал код пакета на `PHP` 8.4.

Ограничения:

- в `JSON` уровня класса нет количества свойств;
- семантика `LOC` отличается от физического количества строк;
- для полной целевой модели агрегатору потребовался бы второй источник или собственный разбор свойств.

### `PDepend`

Плюсы:

- зрелая модель структурных метрик;
- присутствуют `LOC`/`LLOC`, `Ca`/`Ce`, `WMC`, методы и свойства;
- успешно разобрал код пакета на `PHP` 8.4.

Ограничения:

- нет `JSON`-отчёта: доступен `XML`;
- нет `LCOM` в полученном отчёте уровня класса;
- стабильный релиз заметно старше релизов других кандидатов;
- закрывает целевую модель только вместе с дополнительным анализатором.

### `PhpCodeArcheology`

Плюсы:

- единственный проверенный `JSON`, содержащий все требуемые поля уровня класса;
- количество методов и свойств доступно напрямую;
- `LCOM` совпал с `PhpMetrics` на выбранных классах;
- отчёт также содержит метрики истории `Git` и дополнительные данные, полезные следующим задачам эпика;
- успешно разобрал код пакета и отдельный пример `PHP` 8.4.

Ограничения:

- проект моложе конкурентов;
- `JSON` значительно объёмнее необходимой агрегатору модели;
- пакет является плагином `Composer` и требует явного разрешения в `allow-plugins`;
- первый запуск 2.11.3 интерактивно запрашивает подтверждение изменения формул, введённого в 2.7.0;
- поля связанности называются `usedByCount` и `usesCount`; их соответствие принятым в проекте `Ca`/`Ce` нужно явно закрепить в модели метрик.

### Практическая проверка `scc`

`scc` написан на `Go`. Проверена стабильная версия 3.7.0, установленная командой `go install github.com/boyter/scc/v3@latest`.

```bash
scc -a --by-file -f json src
```

Результат для `src/`:

| Показатель | Значение |
|---|---:|
| Файлы | 32 |
| Физические строки | 5 474 |
| Строки кода | 3 951 |
| Строки комментариев | 633 |
| Пустые строки | 890 |
| Оценка сложности | 494 |
| Уникальные строки (`ULOC`) | 1 911 |
| Размер | 180 193 байта |

Результаты по пяти файлам первичной сверки:

| Файл | Строки | Код | Комментарии | Пустые | Оценка сложности |
|---|---:|---:|---:|---:|---:|
| `DtoStructureSniff.php` | 223 | 183 | 0 | 40 | 20 |
| `ServiceStructureSniff.php` | 344 | 256 | 25 | 63 | 36 |
| `EnumStructureSniff.php` | 129 | 104 | 6 | 19 | 9 |
| `CrossModuleDomainRule.php` | 170 | 111 | 34 | 25 | 26 |
| `ServiceContractDependencyRule.php` | 204 | 127 | 49 | 28 | 9 |

`scc` не строит синтаксическое дерево. Он распознаёт код, комментарии и строки конечным автоматом, а сложность оценивает по встреченным ветвлениям и циклам. Поэтому показатель сложности пригоден для быстрого ранжирования файлов одного языка, но не должен подменять `CC`, рассчитанный анализатором синтаксического дерева.

Вывод: **`scc` полезен как отдельный источник метрик уровня проекта и файла, но не является альтернативой `PhpCodeArcheology` для модели уровня класса**. Он соответствует назначению отдельной задачи `TASK-metrics-codebase-size`.

Операционное ограничение: `scc` не является зависимостью `Composer`. Для воспроизводимого запуска потребуется закреплённый внешний бинарник, контейнер или установка через `Go`; версия 3.7.0 требует `Go` 1.25 при сборке из исходников.

### Практическая проверка `Phanalist`

`Phanalist` обработал 32 файла и вернул `JSON` с нарушениями в 30 файлах. Для пяти проверяемых классов правило низкой сцепленности сообщило `LCOM4`: 3, 3, 4, 6 и 8 соответственно. Эти значения нельзя напрямую сравнивать с полем `lcom` других инструментов без фиксации формулы.

При установке пакет имел версию 1.1.10, но загруженный исполняемый файл сообщил версию 1.1.1. Это отдельный риск воспроизводимости упаковки, который нужно перепроверить перед возможным внедрением.

Главное ограничение для агрегатора: метрики находятся в аргументах диагностических сообщений и появляются только при срабатывании правила. Это удобно для контроля качества, но не для полного регулярного снимка всех классов.

### Практическая проверка `php-dep`

`php-dep` обработал 32 файла, нашёл 32 внутренних класса, 58 узлов и 203 ребра без предупреждений. Для пяти проверяемых классов количество исходящих зависимостей равно 4, 2, 2, 4 и 4; входящих — нулю.

Инструмент интересен как независимый источник графа: каждое ребро содержит тип отношения, файл, строку и оценку уверенности. Однако пакет доступен только из ветки `main`, имеет небольшую пользовательскую базу и не измеряет сцепление или сложность. Постоянная зависимость сейчас не оправдана; повторную проверку можно провести после появления стабильного релиза.

### Практическая проверка `PHP Insights` и `PHPLOC`

`PHP Insights` успешно сформировал `JSON` со сводными оценками: качество 86, сложность 39,6, архитектура 94,1, стиль 94 и ноль проблем безопасности. Остальная часть отчёта — найденные нарушения по категориям, а не сырые метрики всех классов.

`PHPLOC` 8.0.7 обработал 32 файла и сообщил 5 474 физических строки, 1 219 логических строк, 32 класса и 231 метод. Встроенная строка версии исполняемого файла при этом осталась 8.0.6. Его `JSON` содержит только агрегаты проекта: минимумы, средние, максимумы и общие количества. Для статистики уровня проекта он пригоден, но `scc` не зависит от версии `PHP`-парсера и покрывает весь многоязычный репозиторий.

## Решение

Основой выбран **`PhpCodeArcheology` 2.11.x**.

Главный критерий — полнота машинного отчёта уровня класса. `PhpCodeArcheology` единственный из проверенных кандидатов предоставляет в одном `JSON` все поля, необходимые запланированному агрегатору, включая количество свойств. Это уменьшает количество источников и собственных вычислений на следующем этапе.

`PhpMetrics` не оставлен как запасная зависимость: совпадение `LCOM` уже зафиксировано, а постоянная установка второго анализатора увеличила бы стоимость поддержки. Его можно временно подключать для повторной перекрёстной проверки формул.

`PDepend` не выбран из-за отсутствия `JSON` и `LCOM` в полученном отчёте. Для целевой модели потребовались бы преобразование `XML` и дополнительный источник метрик.

Расширенный поиск не изменил выбор основы:

- `PhpCodeArcheology` остаётся единственным проверенным инструментом с полным набором полей уровня класса в одном `JSON`;
- `scc` рекомендуется как дополнительный источник размера проекта и файлов, а не как конкурент анализатору уровня класса;
- `php-dep` заслуживает повторной оценки как источник графа зависимостей после стабильного релиза;
- `Phanalist` и `PHP Insights` полезны как диагностические анализаторы, но их отчёты ориентированы на нарушения;
- `PHPLOC`, `php-linter`, `PHP Stability Metrics` и `PHPMD` закрывают только отдельные части модели.

В `composer.json` закреплены:

```json
{
    "require-dev": {
        "php-code-archeology/php-code-archeology": "^2.11"
    },
    "config": {
        "allow-plugins": {
            "php-code-archeology/php-code-archeology": true
        }
    }
}
```

## Ограничения исследования и вопросы для следующих задач

- Формулы метрик не были независимо реализованы и пересчитаны вручную.
- Ненулевой `Ca` не проверен на выбранных пяти классах: `php-dep` также показал нулевое количество входящих зависимостей.
- Проверка `PHP` 8.4 покрывает используемые в пакете конструкции, атрибуты и `readonly`-классы, но не все возможности языка.
- Не исследована стабильность `JSON`-схемы между минорными версиями `PhpCodeArcheology`.
- Не определено, учитывать ли во внешней связанности встроенные типы и типы из зависимостей или только зависимости внутри проекта.
- В модели метрик необходимо формально определить `LOC`, `LLOC`, `LCOM`, `Ca`, `Ce` и `CC` до реализации агрегатора.
- Агрегатор должен читать только закреплённый набор полей и выдавать понятную ошибку при изменении схемы входного `JSON`.
- Поиск альтернатив не является исчерпывающим каталогом всех коммерческих и серверных платформ; приоритет отдавался локальным инструментам с открытым исходным кодом и машинным отчётом.

## Воспроизведение

Команды меняют `composer.json`; невыбранные зависимости после исследования удаляются.

```bash
mkdir -p var/metrics

composer require --dev phpmetrics/phpmetrics:^2.10
vendor/bin/phpmetrics --report-json=var/metrics/phpmetrics.json src

composer require --dev pdepend/pdepend:^2.16
vendor/bin/pdepend --summary-xml=var/metrics/pdepend.xml src

composer config allow-plugins.php-code-archeology/php-code-archeology true
composer require --dev php-code-archeology/php-code-archeology:^2.11
printf 'y\n' | vendor/bin/phpcodearcheology \
    --report-type=json \
    --report-dir=var/metrics/code-archeology \
    src

composer remove --dev phpmetrics/phpmetrics pdepend/pdepend
```

После первого подтверждения версии формул:

```bash
vendor/bin/phpcodearcheology \
    --report-type=json \
    --report-dir=var/metrics/code-archeology \
    src
```

Дополнительные инструменты запускались из изолированных временных каталогов, чтобы не менять зависимости пакета. Команды анализа после установки соответствующего инструмента:

```bash
scc -a --by-file -f json src > /tmp/scc-src.json
phanalist --src src --output-format json > /tmp/phanalist-src.json
php-dep analyze src --format=json -q > /tmp/php-dep-src.json
phpinsights analyse src --format=json --no-interaction > /tmp/phpinsights-src.json
phploc --log-json /tmp/phploc-src.json src
```
