# TASK-feat-transaction-boundary-rule: Ограничение явного управления транзакциями

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Замечание (TasK, 05.08, `CreateByUriCommandHandler`): агент завернул **часть** логики хендлера в блок `if (...) { beginTransaction... commit/rollback }` с try/catch и сбросом — «мне вообще кажется странным там ставить транзакцию и ловить исключение, у нас же атомарность должна быть на уровне всего хендлера, по конвенциям так и по здравому смыслу».
- Конвенции задают принцип («Command Handler выполняет одну логическую транзакцию», `transactions.md`: «транзакциями управляет код хендлера явно через `flush()`», без `doctrine_transaction` middleware), но форму не ограничивают — агенты пишут частичные вложенные транзакции с try/catch, все проверки зелёные.

### Варианты или путь решения (Solution Sketch)
- Phpstan-правило (в духе существующих `Forbidden*Rule`) об ограничении явного transaction API (`beginTransaction`/`commit`/`rollBack`/`wrapInTransaction`):
  - вне Application-слоя (Domain, Integration, Infrastructure, Presentation) — запрет;
  - в теле CommandHandler — только верхний уровень метода: вызовы `beginTransaction` внутри `if`/`try`/`foreach`/замыканий → ошибка (частичная транзакция).
- Перед фиксацией порогов — собрать статистику по потребителям (TasK, stocks2): где сегодня легитимно живут явные транзакции.

### Ожидаемый результат (Expected Result)
- Частичная транзакция внутри условия/try в хендлере ловится статикой; транзакционная логика вне Application невозможна без явного исключения.
