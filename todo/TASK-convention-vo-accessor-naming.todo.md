# TASK-convention-vo-accessor-naming: Конвенция value-object.md: зафиксировать именование аксессоров VO — геттеры get*/is*/has*, мутации только with*

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Конвенция value-object.md описывает инстанс-методы VO семантически («метод либо возвращает значение свойства (геттер), либо вычисляет и возвращает новый VO, либо преобразует в другой тип»), но НЕ фиксирует префиксы аксессоров. Пример конвенции (EmailVo) сам использует короткий `value(): string`. В потребительских проектах возник разнобой: `figi()`, `value()`, `name()` против `getSecurityId()`, `getAsString()` — читатель не отличает взятие значения от вычисления/операции.

### Варианты или путь решения (Solution Sketch)
- Дополнить раздел «Общие правила» и чек-лист value-object.md явным правилом: геттер значения — `getXxx()` (bool — `isXxx()`/`hasXxx()`); префикс отделяет взятие значения от операций (`with*()`, `add()`, `merge()`), конверсий (`to*()`) и фабрик (`create*()`); сеттеры запрещены (VO readonly, «изменение» — новым экземпляром через `with*()`).
- Обновить пример EmailVo в документе: `value()` → `getValue()`.
- Смежные формулировки конвенций, на которые опираться: event.md:50 («доступ через геттеры» для readonly-полей), entity.md:32 («инварианты проверяются в конструкторе или сеттерах» — про сущности).

### Ожидаемый результат (Expected Result)
- Правило зафиксировано в docs/conventions/core-patterns/value-object.md; пример обновлён; потребительские проекты получают однозначный ориентир для ревью (в stocks2 принята формулировка владельцем 2026-11-23; переименование аксессоров там ведётся отдельной задачей техдолга).
