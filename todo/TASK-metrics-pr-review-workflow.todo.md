# TASK-metrics-pr-review-workflow: изменение метрик как артефакт код-ревью

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

- Даже готовый механизм сравнения бесполезен, если в PR нет воспроизводимых снимков «до» и «после».
- ИИ-агенту не задано, когда запускать метрики, какой commit считать базой и как реагировать на ухудшение.
- Результат анализа теряется после CI и не является частью материалов код-ревью.

### Варианты или путь решения (Solution Sketch)

- Снимать `baseline` на merge-base с целевой веткой и `current` на HEAD проверяемого PR.
- Запускать оба измерения в сопоставимом окружении и передавать снимки в команду сравнения.
- Сохранять оба снимка, `comparison.json` и `summary.md` одним артефактом PR.
- Добавить инструкцию ИИ-агенту: изучить дельту до одобрения и потребовать исправление либо явное обоснование регрессии в изменённой области.

### Ожидаемый результат (Expected Result)

- Каждый PR может предоставить воспроизводимое изменение метрик относительно своей целевой ветки.
- ИИ-агент использует дельту как обязательный вход код-ревью наряду с diff кода и конвенциями.
- Кодовая база получает направленность на улучшение: необъяснённые регрессии не проходят ревью незаметно.

## 1. Concept and Goal (Концепция и Цель)

### Story (User Story)

> Когда ИИ-агент проверяет PR, я хочу приложить изменение метрик между merge-base и HEAD, чтобы решение о ревью учитывало измеренное направление изменения качества.

### Goal (Цель по SMART)

Добавить документированный потребительский сценарий и CI-пример, которые получают baseline/current, запускают детерминированное сравнение и публикуют единый артефакт PR. Инструкция ИИ-агента должна требовать анализа регрессий в изменённой области до одобрения. Проверка: сценарий выполняется на тестовом PR TasK и повторно создаёт одинаковую дельту для тех же commit и окружения.

## 2. Context and Scope (Контекст и Границы)

- **Где делаем:** публичный CLI-оркестратор или скрипт пакета, пример CI, README и копируемая конвенция для ИИ-агентов.
- **Базовая ревизия:** merge-base текущего HEAD и целевой ветки PR, а не произвольный последний сохранённый отчёт.
- **Текущая ревизия:** HEAD проверяемого PR вместе с незакоммиченными правками только для локального режима.
- **Границы (Out of Scope):**
  - Не храним долговременную историю в БД.
  - Не публикуем HTML-дашборд как обязательный артефакт ревью.
  - Не одобряем PR автоматически только по отсутствию регрессий метрик.
  - Не скрываем несовместимость снимков под пустым сравнением.

## 3. Requirements (Требования, MoSCoW)

### 🔴 Must Have (Обязательно)

- [ ] Сценарий явно определяет target branch, merge-base и HEAD, сохраняет commit каждого снимка.
- [ ] Baseline и current собираются без изменения отслеживаемых файлов рабочей копии проекта.
- [ ] Окружение, конфигурация и версии измерителей фиксируются; несовместимость блокирует получение результата сравнения.
- [ ] В сравнение передаётся список файлов текущего Git diff для выделения изменённой области.
- [ ] Артефакт PR содержит `baseline/report.json`, `current/report.json`, `comparison.json`, `summary.md` и метаданные воспроизведения.
- [ ] `summary.md` публикуется в доступном для ревью виде; полный JSON остаётся доступен ИИ-агенту.
- [ ] Копируемая инструкция требует от ИИ-агента прочитать `comparison.json`, связать регрессии с diff кода и отразить вывод в ревью.
- [ ] Необъяснённая регрессия в изменённой области является причиной не одобрять ревью; допустимое ухудшение должно быть явно обосновано в PR.
- [ ] Улучшения и устранённые циклы фиксируются в резюме, чтобы агент видел положительный вектор.
- [ ] Сценарий протестирован на PR или паре commit проекта TasK.

### 🟡 Should Have (Желательно)

- [ ] Добавлен пример GitHub Actions с публикацией каталога через artifact и Markdown через job summary.
- [ ] Локальный режим позволяет агенту снять baseline до правок и current после правок без ручного checkout основной рабочей копии.

### ⚫ Won't Have (Не будем делать)

- [ ] Не вводим единый универсальный порог качества для всех проектов.
- [ ] Не считаем отсутствие регрессии достаточным условием одобрения PR.
- [ ] Не требуем HTML-дашборд для машинного код-ревью.

## 4. Implementation Plan (План реализации)

1. [ ] Зафиксировать структуру каталога артефакта и метаданные воспроизведения.
2. [ ] Реализовать безопасный сбор baseline/current через отдельные worktree или эквивалентную изоляцию.
3. [ ] Передать Git diff в сравнение и собрать итоговый артефакт.
4. [ ] Добавить инструкцию код-ревью для ИИ-агента и пример CI проекта-потребителя.
5. [ ] Проверить сценарий на двух ревизиях TasK и покрыть оркестрацию тестами.

## 5. Definition of Done (Критерии приёмки)

- [ ] Для PR одной командой или одним CI job создаётся полный артефакт сравнения.
- [ ] Артефакт однозначно указывает baseline и current commit и позволяет воспроизвести результат.
- [ ] ИИ-агент имеет короткую обязательную инструкцию принятия решения по регрессиям.
- [ ] HTML-дашборд остаётся необязательным представлением для человека.
- [ ] `composer check` зелёный.

## 6. Verification (Самопроверка)

```bash
vendor/bin/coding-standard-metrics-review \
  --base=origin/master \
  --head=HEAD \
  --output=var/metrics/review
test -s var/metrics/review/baseline/report.json
test -s var/metrics/review/current/report.json
test -s var/metrics/review/comparison.json
test -s var/metrics/review/summary.md
composer check
```

## 7. Risks and Dependencies (Риски и зависимости)

- Сбор baseline может требовать отдельной установки зависимостей; рабочая копия пользователя не должна изменяться.
- Изменение `composer.lock`, конфигурации анализа или версии метрики может сделать снимки несовместимыми.
- Покрытие и тестовая статистика зависят от одинакового окружения и набора тестов в обеих ревизиях.
- Для fork PR публикация комментария может быть ограничена правами; artifact и job summary должны работать без write-доступа.

- Метрики являются дополнительным детерминированным входом код-ревью, а не заменой проверки поведения, архитектуры и конвенций.
- Основной артефакт для агента — JSON-дельта; Markdown и HTML предназначены для удобства человека.
