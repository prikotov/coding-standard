# TASK-metrics-composer-integration: запуск метрик в подключаемом проекте

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

- Инструменты метрик входят в пакет, но README показывает команды для анализа самого репозитория `coding-standard`.
- Composer не переносит scripts зависимости в корневой `composer.json`, поэтому добавленный только в пакет script `metrics` не появится в подключаемом проекте.
- Нет полной инструкции, как проекту-потребителю настроить зависимости, конфигурацию, `.gitignore` и одной командой получить `report.json` и HTML-дашборд.

### Варианты или путь решения (Solution Sketch)

- Публичная команда `vendor/bin/coding-standard-metrics` запускается из корня подключаемого проекта и читает его `composer.json`, `.coding-standard.php`, конфигурации Deptrac и PHPUnit.
- Проект-потребитель при желании добавляет `"metrics": "vendor/bin/coding-standard-metrics"` в собственный `composer.json`.
- README описывает установку обязательных инструментов, настройку проекта, запуск, артефакты и типичные ошибки.
- Работа команды проверяется на структуре подключаемого проекта и отдельно на TasK; сам репозиторий `coding-standard` не является целью анализа.

### Ожидаемый результат (Expected Result)

- Разработчик или ИИ-агент подключаемого проекта выполняет документированные шаги и получает `var/metrics/report.json` и `var/metrics/index.html` одной командой.

## 1. Concept and Goal (Концепция и Цель)

### Story (User Story)

> Как разработчик проекта, подключившего `prikotov/coding-standard`, я хочу получить отчёт метрик и HTML-дашборд по своему проекту, чтобы оценивать его поддерживаемость.

### Goal (Цель по SMART)

Предоставить публичную команду `vendor/bin/coding-standard-metrics` и инструкцию по её подключению в проекте-потребителе. Команда должна использовать production-код и конфигурацию потребителя, завершаться ошибкой при невозможности собрать обязательный источник и создавать `var/metrics/report.json` и `var/metrics/index.html`. Проверка: сценарий подключения воспроизводится на TasK, `composer check` пакета остаётся зелёным.

## 2. Context and Scope (Контекст и Границы)

- **Где делаем:** публичные CLI-команды метрик, `composer.json`, шаблон конфигурации Deptrac, README.md, AGENTS.md, тесты и эта задача.
- **Точка запуска:** корень проекта-потребителя, где находятся `composer.json`, `.coding-standard.php`, конфигурации Deptrac и PHPUnit.
- **Область анализа:** только production-классы предметных модулей из Composer `autoload`; пакеты, технические классы вне модулей и `autoload-dev` не включаются в class-level и module-level метрики.
- **Границы (Out of Scope):**
  - Не анализируем `coding-standard` ради отчёта о самом пакете.
  - Не добавляем `composer metrics` в scripts самого пакета как пользовательский интерфейс.
  - Не изменяем `composer.json` и `.gitignore` проекта-потребителя автоматически.
  - Не добавляем CI-гейт по значениям метрик.
  - Не публикуем сгенерированные отчёты.

## 3. Requirements (Требования, MoSCoW)

### 🔴 Must Have (Обязательно)

- [x] Публичная команда `vendor/bin/coding-standard-metrics` запускает полный пайплайн в корне проекта-потребителя и возвращает ненулевой код при ошибке обязательного шага.
- [x] Структурный анализ использует production-корни из Composer `autoload`, исключения и границы модулей из `.coding-standard.php`; `autoload-dev` и классы вне предметных модулей не попадают в метрики модулей.
- [x] Форматтер Deptrac доступен через конфигурацию, копируемую `coding-standard-init`.
- [x] README содержит инструкцию для подключаемого проекта: зависимости, внешние инструменты, конфигурация, `.gitignore`, пример scripts, запуск и пути к артефактам.
- [x] В инструкции явно указано, что scripts Composer зависимостей не наследуются и `composer metrics` добавляется в `composer.json` проекта-потребителя.
- [x] AGENTS.md не предписывает анализировать сам пакет и ссылается на проверку интеграции в проекте-потребителе.
- [x] Автоматические тесты проверяют запуск из структуры проекта-потребителя и создание итоговых артефактов.

## 7. Risks and Dependencies (Риски и зависимости)

- `scc`, PCOV, PHPUnit и Deptrac должны быть доступны в окружении подключаемого проекта; команда обязана сообщать, какого инструмента не хватает.
- Пользовательская конфигурация Deptrac может содержать архитектурные нарушения; отчёт метрик не должен превращать `findings` в CI-гейт.
- Production-корни и модули разных проектов отличаются; источником истины остаются Composer `autoload` и `.coding-standard.php` проекта.
- Новые Composer-зависимости допустимы только из публичного Packagist.

- `README.md` — инструкция подключения пакета.
- Проект TasK — проверка потребительского сценария.
