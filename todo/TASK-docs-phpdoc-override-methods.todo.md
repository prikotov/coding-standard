# TASK-docs-phpdoc-override-methods: PHPDoc для #[Override]/имплементаций интерфейсов — устранить неоднозначность

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)

- В `code-style.md` два правила конфликтуют для `#[Override]`-методов и имплементаций интерфейсов: «PHPDoc обязателен для публичных и защищённых методов» и «Запрет на избыточные комментарии».
- Контракт уже описан в интерфейсе → PHPDoc в имплементации дублирует его (пересказ) и нарушает запрет на избыточность.
- Конвенция случай `#[Override]`/имплементаций явно не разъясняет → разные consumer-продукты применяют правило по-разному.
- Триггер: code review в `prikotov/task-orchestrator` PR #320 (out-of-scope-замечание по `#[Override]`-методам `RolePromptBuilderService` без PHPDoc).

### Варианты или путь решения (Solution Sketch)

- Зафиксировать в `code-style.md` явное правило: по умолчанию контракт интерфейса достаточен, имплементация PHPDoc не дублирует.
- Привести контрпример: когда имплементация **добавляет** информацию сверх интерфейса (поведенческий нюанс, специфичное `@throws`) — PHPDoc уместен и не считается избыточным.
- Согласовать чек-лист ревью (пункт «Публичные … методы имеют PHPDoc» не противоречит новому правилу).
- Явно упомянуть атрибут PHP 8.4 `#[Override]`.

### Ожидаемый результат (Expected Result)

- В `code-style.md` — однозначное правило для имплементаций интерфейсов / `#[Override]`-методов.
- Добавлен пример (достаточность контракта интерфейса + случай с доп. информацией).
- Чек-лист ревью не противоречит правилу.
- Проверка docs/ссылок пакета проходит.

## 1. Concept and Goal (Концепция и Цель)

### Story (User Story)
> Как ревьюер/разработчик consumer-продукта, я хочу однозначное правило о PHPDoc на методах-имплементациях интерфейсов, чтобы не выбирать вручную между «PHPDoc обязателен для публичных методов» и «Запрет на избыточные комментарии».

### Goal (Цель по SMART)
Устранить противоречие в `code-style.md` для случая `#[Override]`-методов и имплементаций интерфейсов: правило «PHPDoc обязателен для публичных и защищённых методов» (§«Комментарии и документация») вступает в конфликт с §«Запрет на избыточные комментарии», т.к. контракт уже описан в интерфейсе, и дублирование его PHPDoc в имплементации — пересказ. Зафиксировать явное правило с примером.

## 2. Context and Scope (Контекст и Границы)

* **Где делаем:** `docs/conventions/principles/code-style.md` — §«Комментарии и документация», чек-лист ревью («Публичные классы, интерфейсы и методы имеют PHPDoc»), блок примеров PHPDoc.
* **Текущее поведение:** требование PHPDoc применяется формально ко всем публичным методам, включая имплементации интерфейсов. Но контракт несёт интерфейс — PHPDoc в имплементации дублирует его и нарушает запрет на избыточные комментарии. Конвенция случай `#[Override]`/имплементаций явно не разъясняет → разные продукты применяют по-разному.
* **Триггер:** code review в `prikotov/task-orchestrator` PR #320 (Ревьювер Бэка Пуаро, out-of-scope-замечание): публичные `#[Override]`-методы `RolePromptBuilderService` без PHPDoc формально нарушают правило, но их добавление было бы избыточным дублированием интерфейса `RolePromptBuilderServiceInterface`.
* **Границы (Out of Scope):**
  - Не меняем общую философию комментирования (PHPDoc для публичного контракта — обязателен; для очевидного — запрещён).
  - Не вводим автоматический снифф/валидатор наличия PHPDoc (отдельная задача, если потребуется).
