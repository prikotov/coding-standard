# TASK-feat-verify-wired-checks: Проверка подключения правил пакета в проекте-потребителе

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Правила живут в пакете, но их доставка в потребитель не проверяется ничем — рассинхрон виден только на ревью.
- Кейс 1 (TasK, 28.07): «я не увидел чтобы подключились проверки на shared dto, они на основе phpstan идут» — правила `DtoReuseRule`/`MessageContractDtoLocationRule` были в пакете, но не были подключены в проекте.
- Кейс 2 (03.08): FQCN-проверки в пакете не было; её добавили только в TasK (`10f33abcc`) — stocks2 и task-orchestrator её не получили вовсе.
- Обновление пакета в потребителях — ручные задачи вида `TASK-build-update-prikotov-coding-standard-026`, повторяются из PR в PR.

### Варианты или путь решения (Solution Sketch)
- Команда `coding-standard-verify` (или флаг у `bin/coding-standard-init`), запускаемая из корня потребителя:
  1. версия `prikotov/coding-standard` в `composer.lock` ниже последнего релиза (Packagist/GitHub API или закэшированный список) → ошибка с командой обновления;
  2. phpstan-extension пакета зарегистрирован в конфиге phpstan потребителя (иначе `Forbidden*Rule`/`DtoReuseRule` молча не работают);
  3. phpcs ruleset потребителя ссылается на пакет.
- Встраивание в `make check` потребителя через init-скрипт: рассинхон версий падает в CI того же PR, где агент дописал код, — обновление пакета происходит в том же PR.

### Ожидаемый результат (Expected Result)
- Состояние «правило есть в пакете, не подключено в проекте» перестаёт существовать незаметно: ловится автоматической проверкой в CI потребителя.
